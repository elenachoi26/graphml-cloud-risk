# Data

## What is here, and what is not

The pipeline reads four input tables. **None of them are distributed in this repository.**

| Input | Contents | Why it is withheld |
|---|---|---|
| `self_features_mapped.csv` | 21 risk features per focal firm per year, extracted from 10-K filings by an LLM | Derived from full-text filings; not redistributed |
| `edges_risk_propagation_valid.csv` | 536 firm→counterparty relationship observations, each with the sentence it came from | Same — every row carries verbatim filing text |
| `incidents_mapped.csv` | 1,071 external risk events matched to graph entities | Sourced from a **commercial risk-data provider under licence**; redistribution is not permitted |
| `master_mapping_canonical.csv` | Canonical entity table — the alias→id mapping behind entity resolution | Built from the two panels above |

`data/raw/` is git-ignored. Drop the real panels there and the pipeline picks them up
automatically.

## What you get instead

**`data/schema/`** — the full variable dictionary for each table: every column, its meaning,
its scale. This is the actual design work, and it is all here.

**`data/samples/`** — a small synthetic panel with identical columns and dtypes, generated by
`tools/make_samples.py`. Five fictional entities, arranged so two focal firms share one
upstream cloud provider — the accumulation case the pipeline exists to detect. A clean clone
runs end to end against these:

```bash
python run_pipeline.py --stage graph
```

`src/utils.load_input()` resolves `data/raw/` first and falls back to `data/samples/`, printing
a banner when it does. Numbers produced from samples are meaningless as risk estimates —
they only prove the code path works.

**A sample run writes to `outputs_sample/`, never to `outputs/`.** The real results cannot be
regenerated without the raw panels, so a clean clone running the pipeline must not be able to
overwrite them with five fictional nodes. `src/config.py` picks the destination from which
inputs are actually present; `outputs_sample/` is git-ignored.

## So what is real in this repo?

Everything in `outputs/` — those are the actual results computed from the real panels:
composite risk scores, node vulnerabilities, the 2025 GCN predictions, the scenario
propagation, the figures. They just cannot be *regenerated* from a clean clone.

Verbatim filing sentences are stripped from every published CSV before commit
(`tools/scrub_outputs.py`, columns listed in `src/config.VERBATIM_TEXT_COLUMNS`). Locally the
pipeline keeps them, because the evidence sentence is what makes a risk score defensible to
an underwriter — see `outputs/interpretation_report/evidence_chain_report.md` for the
structure with the text removed.

## Reconstructing the inputs

1. Select focal firms (this project used Gartner Magic Quadrant categories: Strategic Cloud
   Platform, Cloud DB Management Systems, Data Science & ML Platforms → 12 firms).
2. Collect their 10-K filings for the target years from SEC EDGAR.
3. Run LLM extraction against the schemas in `data/schema/` — one pass for firm-level self
   features, one for counterparty relationships.
4. Resolve entities to canonical ids (`data/schema/master_mapping.md` documents the
   alias→id table; "Amazon Web Services", "AWS" and "Amazon cloud infrastructure" must
   collapse to one node or the concentration measures are wrong).
5. Attach an incident panel keyed on canonical firm id, with `severity`, `reach` and
   `novelty` per event.
